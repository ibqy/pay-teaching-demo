# 对账核心知识点

> 对账是支付系统的最后一道防线，解决「三方支付流水」与「本地订单」不一致问题。

## 为什么需要对账

| 场景 | 风险 |
|------|------|
| 异步通知丢失 | 用户已支付，但商户未收到回调 |
| 渠道单边账 | 渠道扣款成功，本地订单未生成 |
| 金额篡改 | 前端/网络篡改导致本地金额错误 |
| 重复支付 | 超时重试导致同一订单多次扣款 |
| 退款状态不同步 | 渠道已退款，本地未更新 |

即使对接了标准支付流程（下单 → 通知 → 查询 → 退款），**对账仍然是生产环境必不可少的一环**。

## 对账流程

```
   ┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
   │ 下载渠道账单 │ → │ 解析为标准化 │ → │ 逐笔比对     │ → │ 生成差异报告 │
   │ (T+1 定时)  │    │ CSV→Java对象│    │ outTradeNo联│    │ 长款/短款/   │
   └─────────────┘    └──────────────┘    │  Map FULL    │    │ 金额不一致    │
                                          │  OUTER JOIN  │    └──────────────┘
                                          └──────────────┘
```

### ① 下载渠道对账单

- **支付宝**：调用 `alipay.data.dataservice.bill.downloadurl.query` 获取账单下载链接
- **微信**：调用对账单下载 API（V3 接口）直接获取文件流
- 时间：T+1 凌晨执行（D+1 对账前一天的交易）

### ② 解析账单

| 渠道 | 格式 | 编码 | 金额单位 | 特殊处理 |
|------|------|------|----------|----------|
| 支付宝 | CSV，`,` 分隔 | UTF-8 | 元（49.90） | 无 |
| 微信 | CSV，`,` 分隔 | UTF-8 with BOM | 分（4990） | 金额 ÷100 = 元 |

### ③ 逐笔比对

以 `outTradeNo`（商户订单号）为关联键做 FULL OUTER JOIN：

```
渠道记录 Map         本地记录 Map
  ┌─────┐            ┌─────┐
  │ A   │────匹配───→│ A   │  ✅ 一致
  │ B   │────匹配───→│ B   │  ❌ 金额不一致（AMOUNT_MISMATCH）
  │ C   │            │     │  ⚠️ 渠道有、本地无（LONG_SHORT / 长款）
  │     │            │ D   │  ⚠️ 本地有、渠道无（SHORT_LONG / 短款）
  └─────┘            └─────┘
```

### ④ 差异处理

| 差异类型 | 含义 | 常见原因 | 处理方式 |
|----------|------|----------|----------|
| **LONG_SHORT**（长款） | 渠道有、本地无 | 本地订单未入库 / 渠道单边账 | 人工补单 |
| **SHORT_LONG**（短款） | 本地有、渠道无 | 渠道漏单 / 回调失败 | 人工退款/补发 |
| **AMOUNT_MISMATCH** | 金额不一致 | 价格计算错误 / 渠道手续费 | 人工核查 |
| **TIME_MISMATCH** | 时间偏差 > 5min | 支付超时 / 异步处理延迟 | 监控告警 |

## 模块设计

```
reconciliation/
├── downloader/
│   └── BillDownloader.java       接口：获取渠道账单文件流
├── parser/
│   ├── BillParser.java          接口：将文件流解析为 List<ChannelBillRecord>
│   ├── AlipayCsvParser.java     支付宝 CSV 解析实现
│   └── WechatCsvParser.java     微信 CSV 解析实现
├── model/
│   ├── ChannelBillRecord.java   渠道账单记录（标准化后）
│   ├── LocalOrderRecord.java    本地订单记录（对账关心字段）
│   ├── ReconDiff.java           差异记录（类型 + 双方数据）
│   └── ReconReport.java         对账报告（汇总统计 + 差异明细）
└── engine/
    └── ReconciliationEngine.java  对账引擎（核心比对逻辑）
```

## 设计要点

1. **策略模式**：`BillParser` 接口，支付宝/微信各一套实现，新增渠道只需加 Parser
2. **金额统一**：微信对账单单位是"分"，解析时统一转"元"，比对逻辑无需关心渠道差异
3. **Map 比对**：O(n) 复杂度，先 Build 本地 Map，再遍历渠道记录查询
4. **报告驱动**：对账引擎只生成报告，不直接修改订单状态——差异处理留给人工或审批流程

## 延伸知识

- **T+1 对账**：生产环境一般凌晨执行，对前一天数据进行 D+1 对账
- **实时对账**：每笔支付完成后主动查询并比对（成本高，仅关键场景）
- **差异处理系统**：差异自动匹配规则（如 10 元以下自动补单），超过阈值人工处理
- **清算对账**：对账不仅比对交易笔数，还要比对清算金额（排除手续费）
